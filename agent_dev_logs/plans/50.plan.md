## Outcome

**§A's probe was overtaken, not skipped.** It existed to choose between *deleting the
run-time patch and keeping the pin* and *vendoring*. #53 states the preference
(vendor) and the repo owner confirmed it, and vendoring is correct under **either**
probe result: it removes the `git+` requirement itself, so there is no longer a pin
for the E2E lane to override, working image or not. The probe would only have told us
how urgent the second-cheapest fix was.

## Context (as opened)

This image installed `alto-tools` from a **commit pin** at build time
(`setup/requirements.txt:8`, installed by `Dockerfile:38`). The hub's E2E lane then
installed it again from a **moving `master`**, inside the already-published image, at
run time (`e2e-pipeline-smoke.yml:274`).

That is factor V stated as plainly as it can be: a release artifact re-resolving its
own pinned dependency after release. It is roadmap **B9**, unchanged through three
roadmap refreshes, and #53's sweep on 2026-09-09 confirmed it as the last live §2.1 item.

#53's stated preference was to retire the dependency rather than re-pin it: *"just copy
the required files and only the used functionality + reference it in docs clearly."*

## Strategic actions — as executed

### A — Probe first *(superseded, see Outcome)*

```bash
docker run --rm --entrypoint alto-tools ghcr.io/ufal/atrium-alto-postprocess:<published-tag> --version
```

Kept for the record. The probe chose between two fixes; the chosen fix is correct under
either of its outcomes, so it stopped being a gate.

### B — Vendor the two used code paths ✅

The entire dependency surface was **two CLI flags**: `-t` (page text,
`extract_ALTO_2_TXT.py`) and `-s` (statistics, `alto_stats_create.py` — the *only*
reason the git pin existed, since the released 0.1.0 wheel lacks `-s`).

1. ✅ Apache-2.0 licence text carried verbatim into `LICENSES/`, upstream commit
   recorded in `alto_tools.UPSTREAM_COMMIT`.
2. ✅ Subprocess calls → function calls; the `shutil.which` guard deleted, since a guard
   for a binary that can no longer be absent is misleading.
3. ✅ `alto-tools` removed from `setup/requirements.txt`, the comment reworked to say
   where the code now lives and why.
4. ✅ Referenced in the README with upstream origin, commit and licence.

Kept minimal on purpose: copying the upstream module wholesale would re-import code
paths nothing calls — the same maintenance burden in a new place.

### C — Pin the layoutreader clone ✅

`--depth 1` on a branch resolved to whatever the tip was that day. A shallow clone
cannot take a SHA via `--branch`, so: `git init` + `git fetch --depth 1 origin <sha>` +
`git checkout <sha>`, keeping the sparse-checkout of `v3`. Sequence verified against the
live remote before landing.

### D — Sequence with the hub ✅

**#50 landed first, then the hub's Stage 2 restructure.** That ordering was load-bearing:
Stage 2 runs the *checked-out* alto-postprocess source, not the copy baked into the
image, so it needed `alto_tools.py` on `master` first. `6ddabf7` predates `6ba4807`, and
run #130 confirms it held. The constraint is now spent.
