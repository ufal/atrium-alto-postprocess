# [\#37 Issue](https://github.com/ufal/atrium-alto-postprocess/issues/37) `open`: Integration: align extractor JSON-2-TXT with `atrium_document` standard
**Labels**: `development`, `integration`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-08-02 09:56](https://github.com/ufal/atrium-alto-postprocess/issues/37):

The draft JSON-2-TXT extractor introduced in `v1.2.1-beta` currently breaks the downstream architectural contract established with `atrium-llm-enrich`. While the script successfully generalizes the plain text producing path, the ecosystem has since converged on the `atrium_document` standard, which explicitly expects outputs to be structured and mutated inside a shared `doc.json`.

We need to refactor this extractor so it conforms to the paradata-pair accretion model, meaning it must ingest the document JSON, modify only its owned text blocks, and output an updated JSON that is byte-identical for untouched parameters. Additionally, we must implement the missing `--force-single-page` function.

## Context & Rationale
* The current JSON-2-TXT draft causes critical integration gaps because downstream tools now rely on the `atrium_document.schema.json` format.
* Resolving this aligns the `atrium-alto-postprocess` extraction path with the rest of the pipeline's July 31st convergence updates.

## Tasks
- [ ] Refactor the JSON-2-TXT extractor to accept a `doc.json` file as input rather than extracting to an isolated raw text file.
- [ ] Implement the accretion logic: the script must insert/merge extracted text into the designated schema blocks while leaving unrelated metadata untouched.
- [ ] Implement the `--force-single-page` CLI argument and map its logic to the extraction function.
- [ ] Update `README.md` and `setup/config.txt` to reflect the new I/O behavior.

## Acceptance Criteria
- **Schema Conformance:** The output file successfully passes validation against the hub-canonical `atrium_document.schema.json`.
- **Data Preservation:** Untouched parameters from the input JSON remain byte-identical in the output JSON.
- **Feature Completeness:** The `--force-single-page` flag successfully forces multi-page or heavily segmented JSON structures into a single document page output.
- **Testing:** Existing tests are updated, passing, and accurately reflect the new JSON-to-JSON mutation behavior.
