#### Status update by Opus 5,5 for non-ALTO inputs (`--method text-lines`) on `test` (`103e30a`)

**What changed**
- New `--method text-lines` reads any text-bearing file as ordered **pages × lines**, one CSV row per line:
  - PDF, DOCX, ODT/ODS/ODP, XLSX, PPTX, EPUB, RTF
  - HTML/hOCR, PAGE XML, TEI, other XML
  - JSON/JSONL, CSV/TSV, Markdown, plain text (any common encoding, cp1250 first)
- Stages: `text_split.py` → `text_stats_create.py` → `extract_TEXT_2_TXT.py`; classify/aggregate are unchanged.
- Formats are recognised by content, not by extension.
- A page is a real page (PDF, PAGE XML, hOCR, DOCX/ODT page breaks) or a natural block (sheet, slide, JSON child, JSONL record, EPUB chapter, form-feed section).
- A line is the format's own unit (line, paragraph, cell, row); lines over 1000 characters are wrapped.
- Every document also gets a line table, `DOC_LINES_TEXT/<doc>.csv`, written before categorization; its page/line numbers match those `DOC_LINE_CATEG` will use.
- Lightweight readers: standard library + lxml; `pypdfium2` for PDF; `charset-normalizer` for legacy encodings. No PyMuPDF (AGPL).
- Strict handling:
  - each failing file is skipped with a reason code in `ingest_report.csv` (`image_needs_ocr`, `legacy_office_unsupported`, `encrypted`, `corrupt`, `zip_limits_exceeded`, …);
  - zip-bomb and XML-entity guards;
  - PDFs are read in an isolated process with a timeout;
  - document-id collisions are refused;
  - `--strict` makes the run exit non-zero on any failure.
- PDF pages are classified `none` / `garbled` / `ocr` / `digital` in `pages_report.csv`.
- `source.origin` is truthful per class (`ocr:*` vs `digital-born-*`), and `document_hook` keeps positional blocks out of digital-convert's records (§1a).
- `/process` accepts the same formats as `task_type=document`.
- `classify_TEXT.load_page_index` keeps doc ids like `0001` / `NA` as strings.
- `run_pipeline` warns when `--input-csv` does not reach the extract/classify stages.
- ALTO/JSON paths are unchanged: their `--dry-run` output is byte-identical.
- Samples in `data_samples/TEXT/` and `data_samples/JSON/`; reference in `docs/text_inputs.md`.

**Tests**
- Fast suite 1448 → **1581 passed**, 0 failed, on `103e30a`; `ruff` clean; coverage 72.7%.
- All fixtures are built in memory (no binary fixtures); includes an E2E subprocess test chaining stages 1–3.

**Still open**
- Not yet validated on a real OCR-engine export (Azure / Textract / docTR / pero).
- Pre-existing, left as-is for ALTO/JSON parity:
  - `split("-")` in the ALTO/JSON stats scripts breaks hyphenated doc ids;
  - json-keys repeats Azure's header and word text on every page;
  - `--input-csv` only reaches the stats stage (now warned about).

### Status update — 2026-09-24 by Opus 5.5

**Merged.** `--method text-lines` (`103e30a`), the TEITOK follow-ups (`fb72526`) and Phase 4 (`267e334`, `3bd10f9`, `2e2794d`) are on `test` and `master` (`2e2794d`), CI green. Not released yet (after `v1.5.1-beta`).

**New: an input formats reference.** `docs/text_inputs.md` now opens with *Formats and their standards*. It covers every input the repo reads:
- OCR and layout formats: ALTO, PAGE XML, hOCR, ABBYY FineReader XML, DjVuXML, Tesseract TSV, OCR/Doc-AI JSON, PDF text layers, TEI/TEITOK;
- text-bearing documents: office files, EPUB, RTF, HTML, Markdown, CSV/TSV, JSON, plain text, subtitles, e-mail, ZIP bundles.

For each: the standard and its steward, typical producers, what the format records (pages, lines, coordinates, confidences, typography), what this repo keeps and the `source.origin` it records. In short, text and page labels are kept; coordinates, confidences and fonts are not. TEITOK boxes come from ALTO in nlp-enrich (or from flexiconv conversions of PAGE XML/hOCR). The boxes of ABBYY XML, DjVuXML, Tesseract TSV and OCR JSON reach no ATRIUM output.

**Found while writing it**
- `page_split.py` (Step 1 of the ALTO methods) finds pages only in the **ALTO v3** namespace. An ALTO v2 or v4 file prints `No <Page> elements found … Skipping.` and gets no pages and no record. text-lines and the service read every version. This is now documented (README note, §8). The fix — take the namespace from the root element, as `service/utils.py` already does — is proposed, not made.
- nlp-enrich numbers TEITOK pages by their order in the ALTO file, while the ALTO methods use `PHYSICAL_IMG_NR`, and `DOC_LINE_CATEG` has no `page_label`. When the `PHYSICAL_IMG_NR`s are not 1, 2, 3 …, `pb@n` shows ordinals and the record's `pages[]` gets two keys for one page. Documented in §2 here and in nlp-enrich's README (Pitfalls 14).

**Cross-repo:** the hub pages that described this repo as ALTO-only are fixed. Still open:
- hub `KNOWN_PIPELINE_SUFFIXES` and `test_document_required.py`;
- the `ORIGIN_ORIGINATORS` `digital-born` prefix (born-digital kinds that digital-convert cannot read keep `source` only);
- llm-enrich V-1.

The three OCR-engine readers (ABBYY, DjVu, Tesseract TSV) are tested on synthetic samples only.
