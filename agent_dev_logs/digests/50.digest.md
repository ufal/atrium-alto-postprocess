## 🔎 What was wrong (historical — all of this is now gone)

**The pin existed and was installed.** `setup/requirements.txt:8`:

```
alto-tools @ git+https://github.com/cneud/alto-tools.git@1f4f01e5f6ac3562740e39948442973b9cb94be4
```

with the comment above it recording *why* it had to come from git rather than PyPI: the released `alto-tools` 0.1.0 wheel has no `-s` statistics flag at all (verified upstream: `alto-tools -s` → "unrecognized arguments: -s").

**And the E2E lane overrode it.** `e2e-pipeline-smoke.yml:274`, Stage 2, against the already-published image:

```
--entrypoint /bin/sh … -c "pip install https://github.com/cneud/alto-tools/archive/refs/heads/master.zip && export PATH=\"\$PATH:/home/atrium/.local/bin\" && python run_pipeline.py …"
```

A commit pin, overridden by a moving `refs/heads/master`, in the release artifact, at the moment of testing it. Whatever that lane proved, it was not a property of the published image — which is the whole of factor V.

**The `--version` probe was never run, and did not need to be.** It existed to choose between *deleting the runtime patch and keeping the pin* and *vendoring*. Vendoring is correct under **either** outcome, because it removes the requirement the probe was about: there is no longer a pin for the lane to override, working image or not. Recorded here so the skip is a decision, not an omission.

## 🔎 The two call sites — what "only the used functionality" meant

Both shelled out to the CLI; neither imported the package. The entire dependency surface was **two CLI flags**:

| Site                        | Was                                                         | Now                                                            |
|-----------------------------|-------------------------------------------------------------|----------------------------------------------------------------|
| `extract_ALTO_2_TXT.py:104` | `["alto-tools", "-t", str(xml_path)]` — page text to stdout | `alto_tools.text_from_file()`; `shutil.which` guard gone       |
| `alto_stats_create.py`      | `alto-tools -s` — statistics, parsed back out of stdout     | `alto_tools.statistics_from_file()`; the regex round-trip gone |

That is what made #53's "copy only the used functionality" preferred over re-pinning: vendoring the `-t` and `-s` paths removed a `git+` dependency, a `shutil.which` guard, a `PATH` export and the runtime patch in one move, and replaced two subprocess boundaries with two function calls.

**Attribution was already half-done** — `extract_ALTO_2_TXT.py` seeds `alto_tools` as an "always" paradata component carrying Apache-2.0 — but nothing in the tree backed that claim. `LICENSES/alto-tools-Apache-2.0.txt` (upstream verbatim) and `LICENSES/README.md` now do.

**Output parity is pinned, not assumed.** `tests/test_alto_tools.py` holds golden literals captured from the real upstream CLI at commit `1f4f01e5`, plus an independent re-derivation of the extraction over every `data_samples/` ALTO file, plus synthetic fixtures for `<ReadingOrder>`, `@IDNEXT` and `<HYP>` — the paths no sample reaches. Text output is byte-identical to the CLI's stdout; `-s` counts match on every file.
