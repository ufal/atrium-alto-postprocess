## 🎯 Goal & Core Constraint
Digest any text-containing input into ordered plain text (`<format>-2-txt`), so that the per-line
quality categorization runs on any shape of text, OCR output first. The 2026-09-23 re-scope made
this concrete:
* DOCX and PDF must be accepted as ordered pages;
* every sequentially readable textual format should be;
* extracted lines become CSV rows;
* pages and lines encode reading order and blocks for non-paged formats (JSON children, sheets);
* input handling must be strict;
* readers should be lightweight;
* the ALTO workflow is not touched and categorization is not run.

## 🏆 Headline Findings & Conclusions

**1. The status docs had been wrong for two months.**
Plan and digest said "design only" from 07-25, but the JSON design (D1–D8) had landed exactly as
written. The 07-26 comment was right about the real gaps:
* no real JSON sample;
* the deferred `--force-single-page`, since built by #37;
* no E2E test, also since built by #37;
* the disconnect with the `doc.json` contract.

The plan now carries a reconciliation header.

**2. Neither sibling repo has a reader this repo can simply reuse.**
* nlp-enrich's flexiconv→TEITOK path was non-functional (its #10). *(2026-09-24: fixed there on 09-23 and released in
  nlp-enrich v0.21.0; the handoff is described below.)*
* llm-enrich's `digital_to_json.py` (pdfplumber + python-docx) serves another role. It picks the
  format by extension only, has no corrupt/encrypted handling and treats DOCX as one page.

What was reused:
* llm-enrich's PDF text-layer thresholds (`MIN_TEXT_CHARS=3`, 15% garble);
* its deterministic fixture builders;
* its permissive-licence policy (no PyMuPDF).

**3. One lightweight reader library, content-first.**
`text_formats.py` uses stdlib `zipfile` + lxml for every XML/ZIP format, **pypdfium2** for PDF and
**charset-normalizer** for legacy code pages (cp1250 first). Both are lazy, conditional components.
* **Detection:** magic bytes, ZIP members, the XML root and a JSON parse decide. The extension
  only picks among text dialects.
* **Pages:** real pages where the format has them. Otherwise the natural block (sheet, slide, JSON
  child, JSONL record, EPUB chapter, form-feed section).
* **Lines:** the format's own units, capped at 1000 characters. This is also a GPU safety limit:
  the perplexity batch pads to its longest line.

**4. Strict by construction.**
* Every file fails alone, with a stable reason code in `ingest_report.csv`, e.g.
  `image_needs_ocr`, `legacy_office_unsupported`, `encrypted`, `corrupt`, `zip_limits_exceeded`,
  `xml_entity_declaration`, `doc_id_collision`.
* Zip-bomb caps are checked on declared sizes before reading.
* XML is parsed with no entities, DTD or network.
* PDFs are read in a subprocess with a timeout, and page directories are swapped in atomically.
* Symlinks, FIFOs and Office lock files are ignored.
* `--strict` sets the exit code.

**5. Every line has a row — twice.**
* `DOC_LINES_TEXT/<doc>.csv` (`file,page_num,line_num,text,page_label`) is written before any
  categorization. It is built from the list written to the page file, so its numbering equals the
  numbering `DOC_LINE_CATEG` will have.
* Categorization itself (classify/aggregate) is unchanged. Its one tweak is `load_page_index`,
  which stops `0001`/`NA` doc ids being silently dropped.

**6. The `doc.json` contract needed a guard, not just an origin.**
* `source.origin` is truthful per class (the user's decision): `ocr:*` for OCR outputs,
  `digital-born-<kind>` for DOCX, ODT, visible-text PDF and the like.
* `atrium_document` §1a only *warns* when not strict, and the write still happens.
* So `document_hook.write_document_block` now holds back
  `pages`/`content`/`lines`/`tables` for digital-convert's records, unless they carry the
  `needs_ocr` hand-off.
* The CSV outputs are produced either way.

**7. The service speaks the same formats.**
* `/process` accepts every text-lines kind as `task_type=document`.
* `auto` keeps `.txt`/`.json` and decides everything else by content.
* Per-page classification runs in 128-line batches.
* Unsupported uploads get a 400 and unreadable ones a 422, both naming the reason.

**8. ALTO is untouched, measurably.**
* `page_split.py`, both older stats scripts, the three ALTO extractors, `extract_JSON_2_TXT.py` and
  `aggregate_STAT.py` are unchanged.
* The `run_pipeline --dry-run` output for every ALTO/JSON method is byte-identical before and after.
* Tests: 1448 → **1581 passed**, 0 failed. `ruff` is clean; coverage is 72.7%.

## 🔗 TEITOK and the nlp-enrich handoff (2026-09-24)
* **Handoff.** `--method text-lines` writes `DOC_LINE_CATEG/<doc>.csv` (`file, page_num, line_num, text, …, categ,
  quality_score`), which is atrium-nlp-enrich's stage-1 input. Since nlp-enrich v0.21.0 a document can also arrive
  there as a flexiconv conversion (`FLEXICONV_ANNOTATE=true`): a table with the same `doc_id` wins at stage 1, and
  stage 4 takes the page layout from the converted file (nlp-enrich
  [#38](https://github.com/ufal/atrium-nlp-enrich/issues/38)). The text then comes from this repo's reader and the
  layout from flexiconv's, so how well they agree matters; nlp-enrich's round 4 adds an alignment-coverage warning.
* **Page numbers matter downstream now.** nlp-enrich's round 4 makes `page_num` from these tables the page of every
  token (its UDPipe chunks used to be counted as pages), so the numbers written here end up in its NE files, its
  TEITOK `<pb>`s and the document record.
* **TEI/TEITOK input** (`text_formats.read_tei`), checked against nlp-enrich's TEITOK format 2 at `103e30a`:
  pages were renumbered 1..N (`<pb n>` ignored, a page without text dropped), every `</s>` ended a line (format-2
  lines became sentence fragments rather than physical `<lb/>` lines), a legacy `</n>` close tag made a format-1
  file malformed, and there was no TEITOK test. `<dtok>` is harmless; ids, `bbox`, `sameAs` are not needed for text.
  **✅ Fixed 2026-09-24** (on `test` since `fb72526`):
  * every `<pb/>` starts a page, a blank one too, labelled with `pb@n` (else its ordinal) — the pages nlp-enrich's
    TEITOK readers count;
  * in a tokenized document (`<tok>` + `<lb/>`) `<s>` is inline, so lines are the `<lb/>` lines and a sentence
    running over a line or page break (nlp-enrich now puts `<lb/>`/`<pb/>` inside it) is split there;
  * `parse_xml_bytes` repairs `<name>…</n>` exactly (note `name_close_repaired`) instead of recovering, which may
    drop text;
  * three tests in `tests/test_text_formats.py` (page labels and blank pages, a format-2 document with a `<pb/>`
    inside `<s>`/`<name>`, the `</n>` repair); `docs/text_inputs.md` updated. Suite **1588 passed** (1585 at
    `103e30a` in the same environment), 0 failed; `ruff` clean.
* **Issue numbers in code comments — ✅ corrected 2026-09-24.** `document_hook.py:3`, `extract_ALTO_2_TXT.py:190`,
  `classify_TEXT.py:1149,1257`, `aggregate_STAT.py:318`, `page_split.py:527` and `setup/config.txt:2` said
  `atrium-project#13` where they mean atrium-llm-enrich #13 (the document-JSON contract; hub #13 is the CAA paper);
  they now say `atrium-llm-enrich#13`.

## 🧱 Phase 4 — hardening and more dialects (2026-09-24)
K4TEL asked for #31 to be re-inspected against every dev log and the sibling repos (all four fetched at their `test`
HEADs, alto at `fb72526`) and for its gaps in docs, code and config to be closed. The ALTO workflow stays unchanged and
categorization is never run. Decisions D21–D35 are in the plan; what the audit found and what changed:

**1. The OCR text that mattered most came out wrong.**
* Tesseract TSV was one word per line, ABBYY/DjVu XML one character per line.
  * **Now:** own readers (`tesseract-tsv`, `abbyy-xml`, `djvu-xml`, native pages, `ocr:*` origins).
  * Word rows sharing (page, block, par, line) are joined into one line.
* Transkribus PAGE-XML lost its table text. **Now:** TableRegion/TableCell text is read in row/column order, and
  nested regions are placed where they occur.
* Azure Read v3 and Textract JSON gave every line twice (line text + its words). **Now:** line granularity wins at
  any ancestor, and Textract's WORD blocks are dropped when LINE blocks are present.
* A stray `"` in a CSV/TSV swallowed the rest of the file. **Now:** a re-parse without quoting, noted
  `csv_unbalanced_quote`. A numeric-only column is never the text column.
* A real flake: lxml frees element proxies, so `id()` could be reused and a PAGE-XML line skipped. Elements are now
  tracked by identity.

**2. "Strict enough" needed a middle status.** `partial` = read, but with a lossy note (`xml_recovered`,
`decode_replacement`, `csv_unbalanced_quote`, `zip_members_skipped`, `lone_surrogates_dropped`, …).
* A partial document is still processed downstream; `--strict` exits 1 on it as on an error.
* Informational notes (encoding detected, `</n>` repaired) do not count, so the pinned E2E summary holds.

**3. Re-runs and output directories were unsafe.**
* A failed re-run left the previous pages, and they flowed into classify.
* `rmtree` was unguarded: output dir `.` plus an input `setup.txt` deleted `./setup`.
* **Now:**
  * only a real directory of nothing but `<doc>-<n>.txt` is ever replaced;
  * `.tmp-` staging and an `.old-` rename-aside;
  * a failing document's old pages are removed (`stale_pages_removed`).
  * The docs no longer say "atomic".
* One bad document no longer aborts the extract or stats stage. `--strict/--no-strict` works on both stages and
  through `run_pipeline`.

**4. Doc ids in categorization — fixed, never run.**
* classify's and aggregate's re-reads turned `0001` into `1`, and mixed id types crashed aggregate's final sort.
* **Now:** both read `file` as text, aggregate sorts with a natural key, and a missing id is refilled from the CSV stem.
* A replay against the old code on `data_samples/DOC_LINE_CATEG(_gpt)` is byte-identical, so the ALTO output does not
  move.

**5. More sequential formats, one document each.**
* SRT/VTT: one page, a line per cue text line; cue numbers, timings and inline markup dropped.
* EML/MBOX: a page per message, Subject and then text/plain (html fallback), attachments counted.
* gzip/bzip2/xz wrappers, read through under the existing `MAX_FILE_MB`/`ZIP_MAX_RATIO` caps.
* A **ZIP bundle** of per-page OCR files (Transkribus/eScriptorium exports) is read as one document:
  * members in natural path order;
  * metadata and images ignored;
  * one stem in several formats → one kind by precedence;
  * PDFs and nested containers skipped, never read in-process.
* DOCX footnotes and endnotes, and ODT `text:note`, were silently lost. **Now:** `[TEXT_INGEST].NOTES = page|end|skip`
  (default `page`): a footnote's lines end the page that cites it. Headers and footers are counted, not read.

**6. Report-only quality signals, never categories.**
* `mojibake_cp1252`: llm-enrich's codec-derived CP1250↔CP1252 table, made conservative so French text does not trip it.
* `mirrored_text=N` and `rotated_text=N`, from PDF text-object matrices.
* They are page flags in `pages_report.csv`, so the tools' category vocabularies stay disjoint.

**7. The born-digital gap is an ecosystem gap.**
* The hub's `ORIGIN_ORIGINATORS` hands every `digital-born-*` origin to llm-enrich's digital-convert, which reads
  only pdf/docx. xlsx, pptx, odt, ods, odp, epub, rtf and html could therefore only ever be `source`-only records.
* **Now:** `[DOCUMENT].SOURCE_ORIGIN_BY_KIND` (K4TEL's choice) lets a site declare e.g. `xlsx = ocr:generic`, which
  is validated (unknown kind, duplicate, or an origin nobody originates → exit 2).
* The proper fix — narrowing the prefix or extending digital-convert — is a hub follow-up.

**8. Service and docs caught up.**
* The service now honours `[TEXT_INGEST]` and `SOURCE_ORIGIN(_BY_KIND)`, and decodes `.txt` like the batch path.
* Statuses: unsupported → 400, anything else → 422, a zero-line document → 422 `no_text`.
* Both frontends' `accept=` lists are pinned to `supported_extensions()`.
* A bare `--method text-lines` ingested the ALTO samples; it now reads `[PIPELINE].INPUT_DIR_TEXT`
  (`data_samples/TEXT`).
* `docs/text_inputs.md` is rewritten:
  * detection order and matrix;
  * JSON granularity, bundles, blank pages, notes;
  * the page-id note for nlp-enrich;
  * the report columns and statuses;
  * reason codes with HTTP statuses;
  * flags, the origin override and its warning.

**Verification.**
* Suite 1584 → **1707 passed** (11 skipped, 2 xfailed, 0 failed); `ruff` clean.
* `run_pipeline --dry-run` is byte-identical to `fb72526` for eight ALTO/JSON variants.
* Strict E2E on the 20 `data_samples/TEXT` documents (9 new samples, CTX000000016–24): all `ok`, 94/94 line-table
  rows match their page files, and every `doc.json` validates.
* A hostile-input directory (bombs, symlink, FIFO, entity XML, zip-slip, `setup.txt` next to `setup/`) gives a
  reason for every file and writes nothing outside `out/`.
* Categorization was not run.
